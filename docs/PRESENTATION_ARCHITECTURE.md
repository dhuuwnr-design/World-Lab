# WORLD LAB — Presentation Architecture

## Purpose
WORLD LAB is presented as an instrument for exploring possible human worlds, not as a dashboard that pretends to predict one certain future.

The presentation layer must sit on top of the same deterministic, evidence-aware simulation state used by experiments. It must never invent events, causal explanations, people, or certainty that are absent from simulation data.

## Three modes

### WORLD
A cinematic, explorable view of the simulated world.

Navigation hierarchy:
Planet → Country → Region → City → Neighborhood → Household → Person

WORLD shows population structure, movement, technology diffusion, economic activity, institutions, major events, environment, and social conditions at the appropriate scale.

### LAB
The experiment workspace.

A scenario defines:
- population scope and sampling mode
- geography
- starting date
- initial conditions
- intervention or technology
- access/adoption distribution
- duration
- simulation seed
- model version

Experiments can branch from a common baseline. Example branches:
- Baseline
- Technology only
- Technology + education
- Technology + unequal access
- Technology + universal access

Every branch retains parent scenario, seed, model version, inputs, and provenance so results are reproducible.

### SCIENCE
The evidence and validation layer.

For each important result:
Assumptions → Evidence → Model mechanism → Intervention → Simulation → Result → Uncertainty → Validation status

SCIENCE must distinguish:
- implemented mechanics
- calibrated parameters
- fitted results
- held-out validation
- speculative scenarios

## Presentation primitives

### Time Machine
Users can move through simulation time and compare generations, cohorts, events, and system state. The UI should support long horizons without implying that distant outcomes are forecasts with known certainty.

### Why Layer
A macro outcome can be expanded into an evidence-linked event/causal chain. Example:
technology adoption → labor demand → migration → housing pressure → household formation → education → income → fertility → population structure

The chain must be generated from recorded simulation transitions and declared model relationships, not from an LLM inventing a post-hoc explanation.

### People View
A selected simulated person exposes only data represented by the model: household, occupation, education, relationships, wellbeing/social state, experiences, opportunities, constraints, and life-history events. A person's future remains generated by the simulation rather than written as a predetermined story.

### Meet the World
The presentation can follow representative simulated lives across decades. Narration is derived from actual event history and state transitions. Narrative wording may be generated, but factual claims must resolve to simulation records.

### Branching Futures
The same initial world can be replayed and branched into multiple scenarios. Comparisons should show distributions and uncertainty, not only a single winning number.

### Reproducible Replay
A replay identity consists of: model_version + scenario_id + parent_branch + random_seed + input_snapshot + evidence_snapshot

A viewer must be able to reconstruct what produced a displayed result.

## Required data contracts

The presentation layer should consume versioned, serializable records for:

1. WorldSnapshot
   - simulation time
   - geography summaries
   - population summaries
   - sector/system metrics
   - uncertainty metadata

2. EntitySnapshot
   - entity id/type
   - parent/location references
   - observable attributes
   - model-state attributes permitted for presentation

3. EventRecord
   - event id
   - simulation time
   - event type
   - actors/entities
   - causes/inputs
   - effects/state changes
   - provenance

4. ScenarioDefinition
   - scenario id
   - baseline/parent id
   - intervention definition
   - population scope
   - geography
   - start/end time
   - seed
   - model version
   - evidence snapshot id

5. BranchRecord
   - branch id
   - parent branch
   - divergence time
   - scenario id
   - seed
   - model version

6. CausalLink
   - source event/state
   - target event/state
   - mechanism id
   - strength/weight if defined
   - evidence references
   - uncertainty

7. ValidationRecord
   - metric
   - observed reference
   - simulated result
   - error metric
   - threshold
   - validation dataset/version
   - status

8. ProvenanceRecord
   - source
   - source version/year
   - unit
   - transformation/normalization
   - ingestion timestamp
   - evidence snapshot id

## Scale-aware visualization

The viewer must not render every simulated person identically at every zoom level. Aggregation is a presentation operation, not a change to the underlying simulation.

At planetary/country scale: distributions, flows, uncertainty bands.
At city/neighborhood scale: density, infrastructure, migration, economic/social patterns.
At household/person scale: individual trajectories and relationships.

## Scientific integrity rules

1. Never present a simulated outcome as a fact about the real future.
2. Never convert a country label directly into a personality or emotional stereotype.
3. Every externally sourced calibration value keeps provenance.
4. Every causal explanation points to declared model mechanisms and recorded transitions.
5. Every scenario is reproducible from its identity and input snapshot.
6. Uncertainty is displayed wherever the model or evidence supports it.
7. Held-out validation is separate from calibration/fitting.
8. The UI may simplify presentation, but it must not simplify away uncertainty or evidence status.

## Human presentation sequence

A first-time demonstration should feel like this:

1. Start in WORLD at a recognizable year.
2. Zoom from planet to a real region and then to people.
3. Enter LAB and define an intervention and population scope.
4. Run the world through years and generations.
5. Watch multiple branches diverge.
6. Select a macro change and open WHY.
7. Follow the effect into households and individual lives.
8. Open SCIENCE to inspect evidence, assumptions, uncertainty, and validation.
9. Replay or alter the scenario and compare the new branch.

The goal is not to impress people with animated numbers. The goal is to let them experience how a complex world changes while preserving a visible chain from evidence and assumptions to simulated consequences.
